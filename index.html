The patterns

  1. OAuth2 is the dominant auth pattern: 12 of 12 apps support it, and 8 offer both OAuth2 and a static key/token - so most toolkits need an OAuth app registration, with API keys as the quick path for single-tenant use.
  2. Getting credentials is mostly self-serve: 83% of apps let a developer get working credentials alone (free or trial); 1 are gated by an admin, app review, partner programme or sales.
  3. Gating clusters by category: Support and Helpdesk is the most self-serve (100%), CRM and Sales the least (80%).
  4. The most common blocker is 'paid plan' (3 apps); 7 apps are ready today, 5 ready with caveats, 0 blocked.
  5. MCP is already mainstream: 8 vendors ship an official MCP server and 3 more have only community servers.
  6. Composio already has toolkits for 11 of the 12; 0 self-serve, ready apps have no Composio toolkit yet - the cheapest net-new wins.

The agent

1 · DiscoverHint URLs + model-proposed official URLs (Claude WebSearch for the first 38 apps) + GitHub MCP search + Composio's public toolkit catalog, then a one-hop crawl for auth/pricing/MCP links.
→
2 · Fetch & cachePolite HTTP fetch (UA, 1 req/s per host); every page cached with a timestamp. That cache is the only allowed evidence source.
→
3 · Extract (pass 1)A fast model (Claude Haiku) fills the schema from the cached pages and must quote the page for each answer. Snapshot kept as pass1.
→
4 · Loop 1Code-only checks: quote exists in the page, URL returned 200, enum/schema valid, consistency rules, Composio catalog cross-check.
→
5 · Loop 2An independent second agent re-researches each app blind to pass 1; field-level disagreements are flagged.
→
6 · Loop 3Headless Chromium re-renders flagged and JS-built pages; Claude Sonnet adjudicates with fresh quotes, which are re-checked in code.
→
7 · HumanStratified sample (fixed seed) checked by hand against the docs; that sample is the accuracy measurement.

Plain Python, about 1,500 lines. LLM calls go through one wrapper that can use the local claude CLI or the Anthropic API. This run: 95 logged LLM stage calls, about $17 list-price equivalent. Composio is used through its public toolkit catalog (no key needed), with an optional SDK check (Composio().toolkits.get) when COMPOSIO_API_KEY is set.

Limitations and honest failures

  • Discovery depth varied by budget. Apps 1–38 used Claude's web search for discovery. After the CLI hit its usage limit, apps 39–100 used model-proposed URLs plus crawling, which has lower recall for obscure apps.
  • Docs say what's allowed, not what works. Without paid or partner accounts, gated apps are judged from public docs only (as the brief asks). Nothing was tested with live credentials.
  • Breadth is a judgement (narrow/moderate/broad), not an endpoint count. Composio-toolkit presence is an exact name match against Composio's public catalog, which can miss renamed toolkits.
  • Not SaaS: none. These are classified as what they are, not forced into the SaaS mould.
